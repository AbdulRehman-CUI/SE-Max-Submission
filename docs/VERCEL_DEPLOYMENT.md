# Vercel and Neon deployment

This project can be deployed as two Vercel projects from the same Git repository:

```text
se-max-submission (frontend root) -> React/Vite static site
se-max-backend (backend root)     -> FastAPI Python Function
                                      |
                                      v
                                  Neon PostgreSQL
```

The repository does not contain production credentials or deploy automatically. The steps below require access to the Vercel and Neon accounts.

## 1. Prepare Neon

1. Create a Neon project and database.
2. Copy the pooled or serverless PostgreSQL connection string.
3. Keep the connection string private. It belongs only in Vercel backend environment variables.
4. Ensure the URL uses the `postgresql+psycopg://` driver, for example:

   ```text
   postgresql+psycopg://user:password@ep-example.region.aws.neon.tech/spendsense?sslmode=require
   ```

   If Neon supplies `postgresql://`, prepend `+psycopg` to the scheme.

## 2. Create the backend Vercel project

1. In Vercel, import the GitHub repository.
2. Create a separate project named `se-max-backend`.
3. Set **Root Directory** to `backend`.
4. Use the Python runtime detected from [`backend/api/index.py`](../backend/api/index.py). The file exports the existing FastAPI instance; the application is not rebuilt.
5. Do not configure a Node build command for this project.
6. Deploy after setting the environment variables below.

Vercel currently detects FastAPI from supported entrypoints such as `api/index.py`; no legacy `builds` or `routes` configuration is required.

## 3. Backend environment variables

Configure these for **Production**, and add them to Preview if preview deployments should use a separate database:

| Variable | Value |
|----------|-------|
| `DATABASE_URL` | Neon URL using `postgresql+psycopg://...?...sslmode=require` |
| `SECRET_KEY` | A new long random secret, different from local development |
| `DEBUG` | `false` |
| `ALLOWED_ORIGINS` | `https://se-max-submission.vercel.app` |
| `APP_NAME` | `SpendSense` |
| `ALGORITHM` | `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `30` |
| `GEMINI_API_KEY` | Optional server-side Gemini key |
| `GEMINI_MODEL` | Optional Gemini model name |
| `GEMINI_TIMEOUT_SECONDS` | Optional timeout, such as `15` |

Do not add `DATABASE_URL`, `SECRET_KEY`, or `GEMINI_API_KEY` to frontend variables. Vite exposes `VITE_*` values to browser code.

## 4. Run the production migration

Run this from a local checkout after setting `DATABASE_URL` to the Neon connection string. Do not run `create_all` against production:

```powershell
cd backend
$env:DATABASE_URL="postgresql+psycopg://USER:PASSWORD@HOST/DATABASE?sslmode=require"
$env:SECRET_KEY="temporary-local-migration-secret"
.venv\Scripts\alembic upgrade head
```

The migration creates the `users`, `expenses`, and `budgets` tables, including foreign keys, indexes, checks, and the monthly budget uniqueness constraint. It is non-destructive and records its revision in `alembic_version`.

For a future model change:

```powershell
.venv\Scripts\alembic revision --autogenerate -m "describe the schema change"
.venv\Scripts\alembic upgrade head
```

Review autogenerated migrations before applying them. Never run a destructive migration against production without an approved backup and review.

## 5. Verify the backend

After deployment, replace the hostname below with the actual Vercel backend hostname:

```powershell
curl.exe https://se-max-backend.vercel.app/
curl.exe https://se-max-backend.vercel.app/health/db
curl.exe https://se-max-backend.vercel.app/docs
```

Expected results:

- `/` returns `{"app":"SpendSense","status":"running"}`.
- `/health/db` returns HTTP 200 and a safe database health message.
- `/docs` loads the FastAPI OpenAPI interface.

If the database migration has not run, the application may start successfully but protected operations will fail because the tables do not exist.

## 6. Configure the frontend Vercel project

1. Create or open the Vercel project named `se-max-submission`.
2. Set **Root Directory** to `frontend`.
3. Select Vite as the framework.
4. Set this Production environment variable:

   ```text
   VITE_API_BASE_URL=https://se-max-backend.vercel.app
   ```

5. Redeploy the frontend after changing the variable.

The value is read at Vite build time by [`frontend/src/lib/api.ts`](../frontend/src/lib/api.ts). Do not add `/api` when using the separate backend origin.

## 7. Verify authentication and application flows

From the deployed frontend:

1. Open `/register` and create a disposable test account.
2. Sign in at `/login`.
3. Add, edit, and delete an expense.
4. Create and update a budget.
5. Open analytics and insights.
6. If `GEMINI_API_KEY` is configured, verify AI parsing and SMS parsing.
7. Verify logout and that protected pages require sign-in.

The backend accepts the frontend origin through `ALLOWED_ORIGINS`, permits the required methods, and permits `Authorization` and `Content-Type` headers. Credentialed CORS is disabled because the frontend uses bearer tokens rather than cookies.

## Troubleshooting

### HTTP 404 from registration

- Confirm the frontend `VITE_API_BASE_URL` points to the deployed backend, not `/api`.
- Confirm the backend project root is `backend`.
- Confirm the backend deployment exports `app` from `api/index.py`.
- Redeploy the frontend after changing its environment variable.

### HTTP 500 or missing environment variable

- Check Vercel Runtime Logs.
- Confirm `DATABASE_URL` and `SECRET_KEY` are set for the active environment.
- Confirm the database URL uses `postgresql+psycopg://`.
- Do not put backend variables in the frontend project.

### HTTP 502 or Python import error

- Confirm `backend/api/index.py` imports `from app.main import app`.
- Confirm `backend` is the Vercel Root Directory.
- Confirm `requirements.txt` is directly inside that root.
- Redeploy after changing the root directory or dependency manifest.

### CORS error or failed preflight

- Set `ALLOWED_ORIGINS` to the exact frontend origin, including `https://` and excluding a trailing slash.
- Confirm the frontend is calling the backend URL directly.
- Check that the browser request includes only supported methods and headers.

### Database connection failure

- Verify the Neon database is active and the URL is complete.
- Keep `sslmode=require` in the Neon URL.
- Use a pooled Neon connection string where available.
- Check `/health/db` and Vercel Runtime Logs; the API does not expose credentials or stack traces.

### Missing database tables

Run the migration from a trusted local environment:

```powershell
cd backend
.venv\Scripts\alembic upgrade head
```

Make sure the command uses the same Neon database configured in Vercel.

### Incorrect API route prefixes

Backend routes are mounted without an `/api` prefix (`/auth/login`, `/expenses`, `/budgets`, `/v2/analytics/...`). Use `/api` only for the local Vite proxy setup.

## Deployment status

This repository contains deployment preparation and documentation only. A production deployment is complete only after the Vercel projects, Neon database, environment variables, migration, health checks, and browser flows have been verified by the account owner.
